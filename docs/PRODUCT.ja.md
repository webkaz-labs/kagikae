## 何のためのツールか

`kagikae`（コマンド名 `kae`）は、自分の複数の AI コーディング用アカウントを
使い分けるための CLI です。既定では作業環境を共有し、許可された認証部分だけを
切り替えます。設定、スキル、フック、MCP、セッションを毎回作り直す手間を減らします。

環境も分けたい場合は、対応ツールで明示的に独立モードを選びます。
プロファイルに複数のツールをまとめれば、組み合わせを一度に選択できます。

## 用語と使い分け

| 用語 | 利用上の意味 |
|---|---|
| アカウント | 名前を付けて保存した、ツールの認証スナップショット |
| プロファイル | ツールごとに使うアカウントの組み合わせ |
| ディレクトリ固定 | そのディレクトリで使うアカウントと環境の指定 |
| companion | プロファイルに任意で登録する git・gh などの周辺ツール設定 |

用語の詳細は [CONTEXT.md](CONTEXT.md) を参照してください。
保存済みアカウントは、上流サービスで現在も有効なログインであることを保証しません。

| 操作 | 共有環境（既定の `-s`） | 独立環境（`-i`） |
|---|---|---|
| `kae use` | グローバルの認証ストアを切替 | mise を通じてアカウント別の専用ホームを選択 |
| `kae pin` | ディレクトリの認証を分け、設定やセッションを共有 | ディレクトリの作業環境も分離。共有項目は明示指定 |
| `kae run` | 切替後に子プロセスを実行し、終了時に復元を試みる | 子プロセスを独立環境で実行 |

対応範囲と復元条件は [CLI.md](CLI.md) に従います。`run --env` は、保存した
API キーなどを子プロセスの環境変数に渡す別の使い方です。

## 日常利用で得られること

- 作業環境を保ったアカウント切替。
- プロジェクトや worktree ごとの明示的なアカウント選択。
- `status`、`ls`、`doctor` による現在地と認証状態の確認。
- グローバルバックアップと、元のストアに戻す保全記録による復旧手段。
- シェル補完と mise 連携による操作の省力化。

ディレクトリ固定は mise の有効化と信頼設定が前提です。単にディレクトリを
移動しただけでは、必要な環境変数が有効になったとは限りません。

## 対応範囲と限界

モードはツールの能力に応じて制限します。Codex のディレクトリ別 keyring 固定は
実機確認待ちで無効、Cursor の Linux アダプターと Windows 向けリリースは未対応です。
個別の制限は [ADAPTERS.md](ADAPTERS.md) と [ROADMAP.md](ROADMAP.md) を参照してください。

`kae` は上流ツールの認証方式を利用します。上流の更新、認証の失効、同時実行する
プロセスによるトークン更新の影響を受けます。復元は保存済みの内容を戻す操作で、
上流サービス側で失効したログインを有効にし直すものではありません。

`doctor` の上流バージョン警告や確認済みの指紋は、調査の入口です。警告がないことを
認証方式全体の互換性証明として扱わないでください。測定範囲は
[VALIDATION.md](VALIDATION.md) に、実機確認の範囲は [ACCEPTANCE.md](ACCEPTANCE.md) にあります。
